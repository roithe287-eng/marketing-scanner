# URL 원문 기반 비커머스 업종 진단

법무법인, 병의원, 아파트·주택 분양, 보험, 회생·파산·채무조정, 창업, 프랜차이즈의 목적·진단 기준·첫 화면·고객 질문을 같은 페이지 근거로 연결합니다. 기존 커머스·혼합·미확인·구버전 보고서의 시작 구성과 레이더 분기는 유지합니다.

## 판정과 표현

- 제목·설명·H1이 대표 분류를 이끌고 하위 본문 신호에는 상한을 둡니다. 메뉴·헤더·푸터는 업종 근거에서 제외합니다. URL 주소의 단어만으로 업종을 확정하지 않습니다.
- 명시적 문서·교육 구조와 대표 정보 목적은 보존합니다. 부차적인 교육·블로그가 가맹 모집을 덮지 않으며, 보험 칼럼을 보험 상담 랜딩으로 바꾸지 않습니다. 회생·가맹 전문 페이지는 넓은 법률·창업 분류보다 구체적인 기준을 사용합니다.
- 업종별 6개 항목은 실제 원문 신호 또는 보강 검토로 표시합니다. 관측 개수는 품질·검색·전환·법적 적합성 점수가 아닙니다. 담당자·본문·실제 행동 문구를 메타 제목보다 우선 발췌하며 원문을 만들지 않습니다.
- 선택 기준 → 원문 → 개선 방향 → 실제 다음 행동을 데스크톱 3열·태블릿 2열·모바일 1열로 배치합니다. 확인되지 않은 항목을 부재나 실패로 단정하지 않습니다.
- 업종별 질문·검토 조건·제안 제한을 마케팅·콘텐츠·GEO 프롬프트와 기본 질문에 함께 전달합니다. AI가 응답하지 않아도 원문에 있는 서비스 구문을 주제 후보로 우선합니다. 의료 효과, 사건 결과, 보험금 지급, 청약 조건, 창업 수익 등을 임의 생성하지 않습니다.
- 웹·공유 저장 스키마·한 장 요약·업종별 시각 PDF·상세 문서가 같은 목적 데이터를 사용합니다. 업종별 선택 기준을 회사의 실제 제공 사실로 쓰지 않습니다.

## 호환과 적용

선택적 `sitePurpose.sector` 필드로 구버전 스냅샷과 호환합니다. 기존 저장 결과를 소급 재분류하지 않으며, 새 진단에서 현재 URL 원문을 읽습니다. 진단 버전은 `v15-noncommerce-sectors-general-evidence`, GEO 질문 캐시는 `geo-v3.2-noncommerce-sectors`로 구분합니다. 권한·계정·일반 커머스 레이더 점수·보관 정책·외부 수집 경로를 바꾸지 않습니다.

## 검증

- 단위검사 395개와 TypeScript 검사 통과. 합성 7개 업종의 분류·문자 그대로의 원문·목적별 질문·마케팅 카테고리·SSR·문서·시각 PDF·스냅샷 불변성을 검사합니다. 긴 주소 문단보다 직접 업무 설명을 우선하고, 긴 원문은 일치 표현 주변에서 발췌하며 윤리 슬로건을 변호사 이력으로 표시하지 않습니다.
- 격리된 실제 Redis의 API·공유·보관 통합검사 28개 통과. 7개 업종이 실제 분석 API의 수집·진단·스키마 검증·공유 저장·재조회 경로를 통과합니다. 외부 AI와 사이트 응답은 합성 자료로 대체합니다.
- Next.js·Pocket 운영 빌드 통과. 브라우저에서 실제 SSR/CSS의 데스크톱·390px·320px·768px 배치 확인. 새 카드 텍스트 넘침 없음. 관리형 미리보기의 Next CLI 인자 충돌 때문에 정적 SSR 검수 화면을 사용했으며 전체 앱의 브라우저 상호작용 검증과는 구분합니다.
- Pretendard와 실제 PDF 생성 함수로 업종 7개 시각 페이지, 법률형 전체 PDF를 생성해 한글·정렬·줄바꿈·페이지 경계를 확인했습니다. 검수 파일은 합성 자료입니다.
- 로컬 환경의 외부 URL 직접 수집은 DNS 제한으로 미검증입니다. 운영 배포 후 승인된 계정으로 법무법인 URL의 실제 수집→새 분석→업종별 6개 카드 출력을 확인했습니다. 이 검수에서 긴 주소 문단 발췌와 윤리 슬로건의 이력 오탐을 찾아 추가 보정했습니다. 다른 업종의 실제 업체 라이브 진단은 합성 API 검사와 구분합니다.

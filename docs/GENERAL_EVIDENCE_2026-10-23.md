# 일반 웹사이트 전체에 공통 근거 적용 · 2026-10-23

## 범위와 변경

`/api/analyze`의 일반 웹사이트 경로는 도메인·업종 허용 목록 없이 동일한 `finalizeReportEvidence`를 사용합니다. 진짜마케팅 전용 분기는 없습니다. 모든 보조 분석 이후 같은 스키마로 응답을 검사하고 `private, no-store`로 반환합니다. 스마트스토어·브랜드스토어는 기존 제한 분석을 유지합니다. 공개 접근 불가·robots 제한·수집 실패를 정상 분석으로 꾸미지 않습니다.

다른 사이트 유형을 검증하면서 다음 세 가지를 보완했습니다.

- 구매·다운로드 CTA를 문의 CTA로 부르지 않습니다. 문의·상담 CTA와 전체 주요 CTA를 구분하고, 수집 버튼·링크 문구 표본임을 표시합니다. 채널톡·카카오 연락 링크는 실제 호스트로 구분하여 유사 문자열 도메인을 제외합니다.
- 긴 title·description·OG·H1·viewport 때문에 새 근거 필드의 스키마 한도를 넘어 화면 전체가 거부되는 경우를 막습니다. 판정에는 실제 수집값을 사용하고 표시에는 발췌 여부와 원래 글자 수를 남깁니다. H1 요소 전체 수와 수집한 텍스트 표본 수를 구분합니다.
- `pageEvidence.metadataTruncated`에 제목·설명의 보관 발췌 여부를 저장합니다. 불완전한 보관 원문만 보고 ‘키워드 미포함’으로 뒤집지 않습니다. 기존 보고서도 한도 길이에서 잘렸을 가능성이 있으면 해당 필드의 기존 관측을 유지하고, 완전한 다른 필드는 독립적으로 재확인합니다. 원래 빈도·분모·저장 관측은 수정하지 않습니다.

진단 방식은 `marketing-diagnosis-2026-10-v12-general-evidence`로 구분합니다. GEO 외부 측정 프로토콜은 변경하지 않습니다.

## 검증

검증용 공개 페이지 형태는 서비스, 상품 상세, 영문 SaaS, 병원 서브도메인, 정보가 적은 페이지, 다른 도메인으로의 리다이렉트, 한글 도메인, 긴 메타·H1의 8가지입니다. 모두 합성 페이지이며 실제 업체를 분석한 자료가 아닙니다.

- `tests/general-evidence.test.ts`: HTML 수집 → 같은 URL의 근거 → 스키마 왕복 → 화면 렌더링 → PDF의 지표·원문 일치, 발췌 메타와 기존 보관 호환을 검사합니다. 수정 전 구매·다운로드 CTA 분류와 긴 원문 스키마 실패를 재현했습니다.
- `tests/general-evidence.integration.ts`: 실제 API 핸들러·인증·요청 제한·분석 파이프라인·스키마·저장·재열기를 8개 URL에 모두 실행합니다. Redis는 격리된 실제 인스턴스이고 외부 AI·웹 응답만 합성합니다. 실제 고객 저장소와 유료 제공자를 사용하지 않습니다. 테스트용 Redis 브리지는 긴 보고서를 운영체제 인수 한도 때문에 거부하지 않도록 stdin 전달을 지원합니다.
- `tests/browser/general-evidence.cjs`: 위 API 검사에서 내보낸 보고서로 웹 화면의 URL 교체·근거 URL·4개 미측정 표시·320/390/1440px 너비를 확인하고, 쇼핑몰과 긴 원문 보고서의 전체 PDF를 실제 저장합니다. 로컬 운영 빌드와 배포된 사이트에서 같은 검사를 실행할 수 있습니다.

검증 결과: 단위 343개·통합 46개 통과, 타입 검사·운영 빌드 통과. 로컬 운영 브라우저에서 8개 URL을 연속으로 교체해 실행 오류·가로 넘침이 없었고, 전체 PDF 2개의 실제 저장을 확인했습니다. PDF 페이지 수는 합성 보고서에 대한 결과이며 실제 업체의 보고서 분량과 비교하지 않습니다.

브라우저 검사 준비 시 `GENERAL_EVIDENCE_QA_DIR`를 임시 경로로 지정해 통합 검사를 실행하고, 같은 변수를 브라우저 검사에 전달합니다. Playwright/Chromium과 격리 Redis가 필요합니다. `EVIDENCE_TEST_ORIGIN`을 생략하면 로컬 운영 서버를 사용합니다. 외부 배포 검사는 `EVIDENCE_TEST_ORIGIN=https://www.mktscanner.com`으로 지정합니다. 환경의 네트워크 프록시가 필요한 경우에만 `EVIDENCE_USE_PROXY=1`을 사용하며, 격리된 테스트 브라우저에서만 프록시 인증서 신뢰 설정을 적용합니다. 실제 계정·분석·활동 API는 테스트 응답으로 대체됩니다.

새 진단은 모든 일반 웹사이트에 적용됩니다. 접근 차단이나 사이트별 동적 렌더링까지 모두 해소됐다는 의미는 아니며, 실제 외부 AI의 새 답변을 측정한 검증과 구분합니다.

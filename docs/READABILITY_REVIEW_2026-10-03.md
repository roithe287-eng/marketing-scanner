# 상세 설명 보존 및 읽기 편의 검증

## 기준

- 저장된 문제·원인·조치·예시·실행 순서를 자르거나 요약하지 않는다.
- 글자를 줄여 맞추지 않고 박스 높이, 열 수, 줄바꿈을 바꾼다.
- 주요 설명과 실행 가이드는 PC·모바일 모두 16px. 보조 정보는 주로 13–15px.
- Pretendard를 문서 루트, 입력 요소, 모달과 PDF에서 일관되게 사용한다.
- 색상은 근거·해석·실행 등 정보 구분을 보조하며 기존 점수와 판정은 바꾸지 않는다.

## 확인 및 변경

이전 개선은 진단 본문을 축약하지 않았으나 경쟁사 카드의 제목·메타 설명·H1 줄 수 제한, 네이버 접힌 근거의 두 줄 제한, 경쟁사 CTA와 상세 모달의 스키마 타입 목록 일부 생략이 남아 있었다. 모두 제거했다.

공통 근거 박스는 설명 중 하나가 180자를 넘거나 네 줄 이상이면 넓은 세로형으로 바뀐다. 저장된 문자열은 그대로 출력하며 문단 줄바꿈도 유지한다. 상세 내용을 펼치는 기존 기능과 URL별 원문 근거·수정 단계·작성 틀·완료 확인은 유지한다.

경쟁사 카드는 넓은 화면에서도 두 열까지만 사용한다. 좁은 화면의 상세 카드, 일정과 체크리스트는 세로 배치로 공간을 확보한다. AS-IS는 연한 블루, TO-BE는 민트, 해석·작성 틀은 라벤더를 사용하고 일정·네이버 분야에는 필요한 곳에 피치 색을 더했다. 본문은 어두운 색을 유지한다. 파스텔 배경과 해당 강조 글씨의 명암비는 6.18:1 이상이다.

## 검증

- 자동 검사 86개 통과. 긴 한국어·개행·실행 단계·경쟁사 전체 CTA·문장 끝 보존 확인.
- 프로덕션 빌드 통과. 데이터 모델과 점수 산식은 변경하지 않음.
- 전체 PDF의 상세 본문을 14px에서 16px, 소제목을 15px에서 18px로 확대.
- 전체 PDF에서 원문을 순서대로 이어 붙인 결과가 입력 문서 전체와 동일한지 확인. 글자 확대에 따라 페이지가 증가하며 페이지·하단 경계를 침범하지 않음.
- 실제 Pretendard로 검증 PDF 28쪽 생성 및 상세·마지막 페이지 렌더 확인.

## 범위

명시적으로 제공하는 ‘한 장 요약’과 시각 요약은 개요용이며, 전체 PDF 뒤에는 저장된 상세 설명이 포함된다. 수집 시점의 발췌 범위와 데이터 없는 항목은 화면 정리와 구분한다. 저장되지 않은 원문을 복원하거나 새로운 실측 결과를 만들지 않는다. 실제 휴대폰과 신규 URL 진단 전 과정의 검증으로 표현하지 않는다.

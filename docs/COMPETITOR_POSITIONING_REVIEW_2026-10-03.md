# 경쟁사 검색·메시지 포지셔닝 개선

검토일: 2026-10-03. 적용 규칙: `message-evidence-v2`.

## 확인한 공식 범위

- 네이버 웹문서 검색 API는 `query`, `display`, `start` 기반 웹문서 결과를 반환한다. `total`은 총 검색 결과 수이며 키워드 검색량이 아니다. 제목·링크·설명은 업체 매출·시장점유율·통합검색 순위의 증거가 아니다.
- 공식 문서: https://developers.naver.com/docs/serviceapi/search/web/web.md
- 검색량은 별도 검색광고 API 등 적절한 데이터 원천의 인증·집계 범위가 필요하다. 현재 스캐너의 해당 연결은 미연동이며 검색량을 만들어내지 않는다. https://naver.github.io/searchad-apidoc/

## 선정 과정

1. 원문 제목·설명·H1·H2·메타 키워드에서 업종/제품 표현을 선택한다. AI가 제안한 검색어도 구성 단어가 원문에 있는지 확인한다. 원문에 없는 업종·지역을 조합하면 규칙 기반 후보로 대체한다.
2. 웹문서 API 30건을 요청한다. 검색 시각, 시작 위치, 실제 응답 수, 조회한 검색어를 저장한다. 최종 검색어의 결과만 비교한다.
3. 자사, 동일 도메인 중복, 알려진 포털·대형몰·SNS, 명확하게 다른 역할의 페이지를 제외한다. 기업 규모 전체를 식별하는 분류기가 아니며 같은 회사의 다른 도메인까지 합치지 않는다.
4. 통과 후보 중 API 응답 순서대로 최대 8개 페이지를 동시에 수집한다. 페이지 제목·설명·H1의 검색어 관련 표현 확인 여부와 API 응답 순서로 최종 최대 5개를 선택한다. 수집 한도로 보류된 개수도 기록한다.
5. 직접 경쟁 관계는 상품/서비스·지역·고객층·판매 방식을 검토해야 한다. API 순서, 재정렬한 비교 번호, 경쟁 적합성은 다른 정보다.

## 두 축

공통 입력은 페이지 제목과 메타 설명이다. 새 수집에서는 OG 설명으로 대체하지 않는다. 구버전 후보의 OG 대체 여부는 알 수 없어 화면에 명시한다. AI 해석과 검색 요약은 좌표에서 제외한다.

- **X 검색어 연결도**: 공백·대소문자를 보정한 대표 검색어 구성 단어 중 두 필드에 한 번 이상 나타난 단어의 비율. 동의어나 검색 의도 전체를 평가하지 않는다. 반복 횟수는 좌표를 바꾸지 않는다.
- **Y 선택 정보 범위**: 가격·조건 / 대상·범위 / 사례·근거 / 진행·지원의 관련 표현 종류마다 25점. 단독 ‘원’·‘%’는 가격 신호가 아니다. 표현 바로 뒤의 명시적인 부재·미보유·불가·예정 등은 제외한다. 문장의 모든 의미를 이해하거나 사실을 검증하는 모델은 아니다.
- 두 필드가 모두 없으면 판정 보류한다. 수집 실패를 0이나 중앙 좌표로 대체하지 않는다. 두 필드가 있으나 탐지가 없으면 실제 0 지수는 표시한다.
- 50은 안내선이다. 업종 평균·합격선·백분위·성과 확률이 아니다. 우상단은 시장 우위가 아니고 빈 공간은 시장 수요의 증거가 아니다.

## 화면 및 내보내기

- 본문에 노출되는 자사+후보 지도, 두 축 설명, 선정 흐름, 같은 좌표 묶음, 키보드/터치로 선택 가능한 업체 목록, 계산 원문, 개별 표현 체크.
- 자사에 필요한 수정 위치와 TO-BE 작성 틀, 작업 지시서 복사, 실제로 전후 비교할 KPI. 검색량·전환 상승률을 추정하지 않는다.
- 임의의 가격/프리미엄·감성/실용 좌표, H1 길이·CTA 개수 기반 강약점 평균은 제거한다. 저장된 원문과 딥다이브 기능은 유지한다.
- 새 선정 기록과 자사 원문은 공유 스키마에 보존한다. 이전 보고서는 새 기록을 만들어내지 않는다.
- PDF 지도는 자사와 첫 5개 후보를 표시한다. 상세 PDF에는 모든 후보의 좌표·근거·원문·작성 틀을 포함한다.

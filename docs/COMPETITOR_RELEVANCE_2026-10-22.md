# 경쟁사 후보 관련성 교정

## 재현한 문제

온누리스토어 첫 화면은 수집 범위에서 회사명 외 상품 설명을 충분히 제공하지 않았습니다. 기존 로직이 회사명 `온누리스토어`를 fallback 검색어로 선택하고, 사람인·블라인드·원티드·더브이씨·잡플래닛 등의 기업/채용 정보를 비교 후보로 포함했습니다. 최종 단계는 검색어 일치가 없어도 `needs_review`로 남겨 최대 5곳을 채우고 있었습니다.

## 새 기준

- 회사명·브랜드명 단독 검색을 상품·서비스 시장 검색으로 사용하지 않습니다. 수집된 입력 페이지의 제목·설명·주요 제목·메타 키워드·본문에서 확인한 실제 상품·서비스 표현만 사용합니다.
- 이미 수집한 자사 본문 중 메뉴·푸터·판매업 신고 등은 제외하고 최대 8,000자를 재사용합니다. 검색 API 결과를 AI에 전달하지 않습니다.
- 채용·연봉·기업정보·기사·블로그 페이지를 도메인 및 페이지 역할로 먼저 제외합니다. 실제 채용 서비스 검색에는 채용 플랫폼을 허용합니다. 도메인 경계를 검사하므로 유사 이름의 다른 사이트는 차단하지 않습니다.
- 검색어 일치도가 높은 후보를 우선 확인하되, 후보 페이지 수집은 기존 최대 8곳을 유지합니다. API 원래 응답 순서는 별도로 보존합니다.
- 후보 페이지 제목·메타 설명·H1에서 검색어 구성 표현의 일치를 확인해야 최종 비교에 포함합니다. 수집 실패·원문 부족·관련성 미확인은 제외하고, 5곳 미만 또는 0곳도 정상 결과로 보존합니다.
- 회사명 외 근거가 부족하면 검색을 보류하고 상세 URL 안내를 반환합니다. `research.selectionStatus`와 `selectionMessage`를 저장해 부족한 출처와 후보 부재를 구분합니다.
- `filtering.policyVersion=2`. 기존 `1` 보고서도 호환됩니다. 기존 보고서를 표시할 때 명확한 비제공 페이지를 재제외하며 저장된 기록은 변경하지 않습니다. 화면·공유·PDF가 같은 표시 규칙을 사용합니다.

## 한계

검색어와 원문 표현의 일치는 직접 경쟁 관계를 보장하지 않습니다. 실제 고객층·지역·판매 방식은 대조가 필요합니다. 동적 페이지의 상품 설명을 확보하지 못한 상태에서 외부 기업정보로 업종을 추측하거나 경쟁사 수를 채우지 않습니다. 기존 PDF 파일 자체는 바뀌지 않으므로 최신 검증 결과는 재진단 및 새 다운로드가 필요합니다.

## 검증 위치

`tests/competitor-relevance.test.ts`는 온누리스토어 사례, 5개 잘못된 플랫폼, 실제 판매처 통과, 채용 업종 예외, 유사 도메인, 푸터 제외, 수집 실패·메타 불일치, API/AI 입력 분리, 이전 보고서·PDF 동작을 검사합니다. 기존 위치·원문·응답 순서 테스트도 새 제외 정책에 맞춰 검증합니다.

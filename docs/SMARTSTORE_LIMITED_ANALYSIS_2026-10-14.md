# 스마트스토어·브랜드스토어 제한 분석 · 2026-10-14

## 변경 이유
관리자 활동 이력의 targetHost가 입력 URL에서 hostname만 저장하므로 서로 다른 스마트스토어가 하나로 집계되었습니다. 실제 기존 분석 요청은 전체 URL을 유지하고 있었으므로 표시 오류와 수집 제한은 서로 다른 문제입니다.

## 구현
- 스마트스토어·브랜드스토어의 업체 식별자를 활동 대상에 포함. 모바일 호스트는 기본 호스트로 통일. 상품 경로는 분석에 유지하며 관리자 합계는 스토어 단위로 묶습니다. 쿼리·프래그먼트·인증정보는 기록하지 않습니다.
- 신규 API 응답 kind=smartstore를 일반 MarketingReport와 분리. 일반 점수·레이더·SEO 전체 진단·GEO·경쟁사·PDF/공유 기능으로 전달하지 않습니다.
- URL 입력 시 플랫폼 이름에 맞춘 제한 안내(brand.naver.com/dongwon 포함). 업체 식별자 없는 URL은 요청 전과 서버 양쪽에서 거절. 스토어 홈 및 /products/숫자 상세 주소 지원.
- 공개 HTML의 제목·설명·공유 제목·공유 설명, 상품 페이지의 공개 Product 구조화 데이터 이름·설명만 표시.
- 수집기 신원을 표시하고 robots 규칙을 먼저 확인. 접근 거절·속도 제한·정책 확인 실패·로그인/보안 확인 화면은 제한 결과로 반환. 리다이렉트는 따라가지 않으며 최종 URL 입력을 안내. 비공개 API·쿠키·우회 호스트를 사용하지 않음.
- 분석 가능한 콘텐츠가 없으면 quota refund. 성공/실패와 구분한 analyze_limited 이벤트 기록. 제한 결과는 미완료 집계에서 제외.
- 과거에 도메인만 기록된 업체 식별자는 소급 복원하지 않음. 기존 기록/접근 통제/보관 기간 유지.

## 섹션별 적용 범위
- 일반 웹사이트 보고서와 공통인 5개 챕터(핵심 요약 / AI·GEO / 검색·페이지 / 경쟁사 / 실행 과제)를 유지합니다.
- 수집 범위와 공개 제목·설명·상품 정보는 실제 관측만 표시합니다. 수집 불가 상태는 ‘자료 확인 불가’로 표시하며 콘텐츠가 없거나 품질이 낮다는 판단으로 바꾸지 않습니다.
- 판매자 직접 확인 안내, 직접 입력형 목표·예산 계산기는 활성화합니다. 목표 계산기에 스토어용 입력 안내와 채널을 적용하고 웹사이트의 GA4 기본 안내는 유지합니다. 계산기 값은 진단 데이터로 저장하지 않습니다.
- 웹사이트 점수/비교/전환 동선, GEO, 키워드 빈도/순위/기술 SEO, 경쟁사, 자동 실행 과제 등 27개 미적용 섹션에 각각 가상 예시 화면을 표시합니다.
- 각 예시에 ‘이 스토어의 분석값이 아닙니다’, ‘스마트스토어·브랜드스토어는 미적용’과 해당 이유를 표시합니다. 예시 본문만 블러 처리하고 inert·aria-hidden으로 상호작용과 보조기기 읽기를 차단합니다. 인쇄에서도 블러와 안내를 유지합니다.
- 예시 값은 UI 전용이며 API 응답·점수·공유/PDF로 전달하지 않습니다. 기존 스토어 응답 kind=smartstore와 일반 MarketingReport의 구분은 유지합니다.

## 검증
- 전체 자동 테스트 269개 통과: URL 구분, 경로 보존, 개인정보 제거, 수집 허용/거절, 오류 화면 오탐 방지, API 접근 통제, 일반 파이프라인 유지, 제한 이벤트와 환불 명령, 27개 예시 격리와 브랜드스토어 서버 렌더링 포함.
- 타입 검사 및 프로덕션 빌드 확인.
- 테스트용 Redis 전송 응답을 사용해 새 분기와 환불 명령을 확인했으며, 운영 Redis 변경이나 실판매자 계정 연동 검증은 아님.
- tests/browser/smartstore.cjs를 Chromium 153으로 실행 완료: 스마트스토어/브랜드스토어 입력 안내, 업체 식별자 검증, 5개 챕터/27개 블러, 인쇄 스타일, 목차 이동, 목표/예산 계산, 브랜드스토어 홈/모바일 상품 경로, 새 진단 시 계산기 초기화, 실패 시 결과 보존, 일반 웹사이트 전환을 확인. 320/390/768/1440px에서 가로 넘침과 오버레이 잘림이 없고 브라우저 오류 0건. 데스크톱·모바일 블러 카드와 브랜드스토어 헤더 캡처를 육안 확인.
- 브라우저 검수는 로컬 API 응답 fixture를 사용합니다. 실스토어 수집 또는 운영 계정의 결과를 대신하지 않습니다. Chromium 런타임은 임시 검수 환경에만 설치하고 앱 의존성은 추가하지 않았습니다.
- 실제 wodkq 요청에서는 수집 정책 확인 불가로 제한 결과 반환. 외부 실스토어 콘텐츠 수집 성공을 확인한 것은 아님.

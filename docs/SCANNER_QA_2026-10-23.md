# 마케팅스캐너 운영 검증 · 2026-10-23

## 실제 운영 흐름에서 확인한 문제와 수정

1. Cafe24의 `/board/product/write.html?product_no=...`을 상품 상세 경로로 인식하여 `WRITE`가 상품 표본에 포함됐습니다. 게시판·커뮤니티 경로와 상품 카드의 후기·문의·작성 버튼 문구를 상품 근거에서 제외합니다. 정상 상품 상세 경로는 유지합니다.
2. 윈세이 분석의 GEO 기본 질문이 `BEST ITEMS 선택 시 ...`로 생성됐습니다. 공통 매장 제목을 시장 키워드에서 제외하고, 기존 사전에 없는 품목도 서로 다른 공개 상품명 및 페이지 설명에서 확인한 단어를 후보로 사용합니다. 괄호 안 브랜드 별칭·스토어 접미사, 숫자가 섞인 모델·규격, 일반 수식어를 구분합니다. GEO의 상품 주제는 실제 상품명·분류·설명 근거가 있는 후보로 제한합니다.
3. 서비스형 사이트에서 상품 원문이 0개인데도 보고서가 ‘메인 HTML 밖의 상품 정보도 함께 확인했습니다’라고 안내했습니다. 상품 표본이 있는 경우와 미확인 상태를 구분하여 표시하고, 서비스 본문을 기준으로 진단한다는 안내를 제공합니다. PDF에서도 같은 구분을 적용합니다.

GEO 캐시를 `geo-v2.8-grounded-product-topics`, 진단 방식을 `marketing-diagnosis-2026-10-v9`로 분리합니다. 기존 보관 보고서의 원본 답변·측정값은 재작성하지 않습니다.

## 검증 근거

- 수정 전 재현 검사: 게시판 상품 경로, 버튼 문구, `BEST ITEMS` 주제 선택의 세 가지 실패를 확인했습니다.
- `tests/general-domain-products.test.ts`: 다양한 플랫폼 경로·robots·사이트맵·카테고리·상품 표본·서비스형 사이트·GEO/추천 질문 연결을 검사합니다. 새 사례에는 사전에 없는 제습기, 브랜드 별칭, `1등급`과 모델 번호도 포함합니다.
- 전체 단위 검사: `npm test` (327개).
- 타입 검사: `npm run typecheck`.
- 운영 빌드: `npm run build` (포켓 앱 빌드 포함, 로컬에서는 운영 저장소 마이그레이션 생략).
- 저장·권한 통합 검사: `node --import tsx --test tests/*.integration.ts` (38개). 공식 Ubuntu Redis 7 패키지의 실행 파일을 별도 임시 경로에 풀어 사용하며, 테스트마다 격리된 루프백 Redis와 가짜 토큰을 사용합니다. 실제 고객 저장소나 메일 발송은 사용하지 않습니다.
- 만료 검사의 엄격한 밀리초 동등 비교는 Redis TIME/PTTL 측정 시차로 2ms 차이가 생겼습니다. 실제 정책인 ‘기존 만료일을 연장하지 않음’을 검증하며, 저장된 생성·만료 시각이 변경되지 않는지도 별도로 확인합니다. 운영 보관 로직은 변경하지 않습니다.

## 운영 화면에서 확인한 범위

- 윈세이 일반 쇼핑몰: 분석 완료, 상품 표본 12개·비교 후보 4개, GEO 답변 표시.
- 진짜마케팅 서비스형 사이트: 분석 완료, 비교 후보 5개, 상품 미확인 상태에서도 서비스 본문으로 진단.
- 계정으로 보고서 보관 후 같은 브라우저에서 보관 링크 재열람, 7일 만료 안내 표시.
- 공개되지 않은 내부 주소 입력 차단, 실패 후 이전 정상 보고서 유지.
- 전체 상세 PDF와 한 장 요약 PDF 생성 완료. 모든 고유 원문·근거·안내를 포함하는 전체 PDF는 윈세이 사례에서 489페이지·약 36초였으며, 한 장 요약은 1페이지·약 1.3초였습니다.

브라우저 자동화의 `blob:` URL 정책 때문에 생성된 PDF의 실제 파일 내부·인쇄 결과는 이 운영 점검에서 열람하지 못했습니다. PDF 생성 성공을 파일 전체의 시각 검수로 해석하지 않습니다. Vercel 런타임 로그도 연결 권한 제한으로 확인하지 못했으며, 운영 UI·저장 링크·격리된 통합 검사 결과를 구분해 기록합니다.

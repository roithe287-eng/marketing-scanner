# 이용 문의 이메일 알림 연결

새 문의를 저장한 뒤 Resend에 이메일 발송을 요청합니다. 네이버·메타 복수 선택과 선택한 이용권, 문의자 이름·회사, 관리자 화면 링크가 포함됩니다. 연락처와 전체 문의 내용은 관리자 로그인 후 확인합니다.

## 최초 연결

1. Resend에서 사용할 발신 도메인을 인증합니다. 발송 권한만 있는 API 키를 준비합니다.
2. Vercel의 `marketing-scanner` 프로젝트 → Settings → Environment Variables에서 **Production**에 다음 값을 등록합니다.
   - `RESEND_API_KEY`: 발송 전용 키. Sensitive로 저장하며 채팅이나 소스 코드에 붙여 넣지 않습니다.
   - `INQUIRY_EMAIL_FROM`: 인증된 도메인의 단일 발신 이메일 주소. 표시 이름/꺾쇠 없이 이메일만 입력합니다.
   - `INQUIRY_NOTIFY_TO`: 선택 사항. 생략하면 소유자 관리자 계정의 이메일로 전송합니다. 다른 수신 주소를 사용할 때만 단일 이메일을 설정합니다.
3. Production을 재배포합니다. 관리자 → 이용 문의에서 연결 상태와 수신 주소를 확인합니다.
4. 실제 문의 또는 명확히 구분된 테스트 문의를 접수하고 관리자 발송 상태, 실제 수신함/스팸함을 함께 확인합니다. 설정 전 문의는 자동 소급 발송되지 않으며 필요 시 문의의 `알림 보내기`를 사용합니다.

## 실패와 재시도

- 문의 접수와 이메일 발송 상태는 별도로 저장됩니다. 메일 설정 누락, 발송 오류, 제한 시간 초과가 발생해도 접수는 유지됩니다.
- 메일 요청은 최대 5초로 제한합니다. 실패한 항목은 관리자의 `알림 재시도`로 다시 요청합니다.
- 재시도에는 소유자 로그인, 등록 네트워크, 동일 출처, 문의별 시간당 3회 제한을 적용합니다.
- 동시 실행 잠금 및 고정 Idempotency-Key를 사용합니다. 이미 발송 요청이 완료된 문의는 다시 전송하지 않습니다. Resend 중복 방지 키는 24시간 유효하므로, 발송 직후 저장소 장애로 결과 기록이 유실된 경우 24시간 이후 재시도 전 공급자 발송 로그를 확인합니다.
- `발송 요청 완료`는 공급자가 요청을 수락했다는 뜻입니다. 실제 수신·열람을 의미하지 않습니다.
- 이메일 상태는 문의의 남은 90일 보관기간에 맞춰 만료되며 재시도로 보관기간을 연장하지 않습니다.
- Preview와 로컬 개발 환경에서는 키가 있어도 이메일을 전송하지 않습니다.

# 관측 근거와 보고서 판정 일치 · 2026-10-23

## 문제와 변경

진짜마케팅 보고서에서 H1·연락처·키워드의 요약과 상세 판정이 달랐고, 실제로 측정하지 않은 화면·전환·모바일에 AI 숫자 평가가 붙었습니다. 브랜드와 도메인을 명시한 질문에서만 발생한 인용을 전체 질문의 20%로만 강조하는 문제도 있었습니다.

새 분석 결과에는 `evidenceReview`를 저장합니다. API가 모든 보조 분석을 모은 뒤 `finalizeReportEvidence`를 한 번 적용하여 체크리스트·요약·이슈·일정·상담 안내·발견성의 H1/연락처 내용을 같은 관측값으로 맞춥니다.

- 대표 지표: **HTML 기본 항목 충족 현황**. 제목·설명·OG·H1·ALT 속성·viewport의 6가지 자체 기준을 같은 비중으로 집계합니다. 판정 가능한 항목을 분모로 사용하고 미확인은 제외합니다. 원문·선택자·URL·수집 시각·산식을 함께 저장합니다.
- 복수 H1만으로 기본 항목을 감점하지 않습니다. H1 존재와 렌더링 후 대표성·기기별 복제 여부를 구분합니다. 별도 네이버/Google 기준의 적용 범위도 유지합니다.
- 첫 화면·문의 완료 흐름·광고 랜딩·모바일 UX는 **미측정**으로 표시합니다. 문서만 보고 점수를 확정하지 않습니다. 후기·인증·가격 관련 단어를 감지해도 실제 자료 검증은 **검토** 상태입니다.
- 전화번호 패턴 미감지를 연락처 부재로 확정하지 않습니다. 문의 CTA·폼·전화·이메일·채널톡·카카오 경로의 관측과 실제 동선 확인을 구분합니다. 수집한 연락 링크 표시는 길이를 제한합니다.
- 원문에 근거하지 않은 AI 이슈는 검토 의견으로 표시합니다. CTA 개수·반복 횟수만으로 집중도 저하·전환 손실을 확정하거나 긴급 수정으로 올리지 않습니다.
- 새 보고서의 GEO 준비도·업종 비교·전후 레이더에 검증되지 않은 AI 숫자 평가를 제시하지 않습니다. 기존 숫자 필드는 이전 API 소비자와 보관 스키마 호환을 위한 내부 자료이며, 새 보고서의 대표 지표로 사용하지 않습니다.

## 키워드와 AI 관측

`containsKeyword`와 `reconcileKeywordMetadata`를 공통으로 사용합니다. 제목·설명 포함 여부를 동일한 수집 원문에서 계산하고, 한국어 복합어 안의 표현도 포함으로 처리합니다. 영어는 단어 경계를 확인합니다. 이는 표현 포함 여부이며 의미·검색 수요 판정이 아닙니다. 보관 결과는 같은 URL의 저장된 `pageEvidence`가 있을 때만 표시용 포함 여부를 다시 대조합니다. 단어 횟수·분모·원래 저장 데이터는 수정하지 않습니다.

AI 관측은 브랜드 포함/미포함 질문을 주 지표로 나눠 **분자/분모**를 함께 표시합니다. 전체 질문 인용과 브랜드 언급은 보조 수치입니다. 브랜드 포함 여부가 없는 기록은 미분류로 남기며 미포함 분모에 넣지 않습니다. 실패·검색 미확인·중복 질문은 계속 판정 분모에서 제외합니다. 저장된 합계가 오래된 경우에는 기존 응답 행에서 재집계하며 새 API 측정으로 표시하지 않습니다.

## PDF

한 장 요약, 시각화, 상세 PDF가 같은 표시용 보고서와 `evidenceReview`를 사용합니다. HTML 관측 충족 현황과 미측정을 표시하고, 원문에서 확인한 수집 문제를 미측정 UX 제안보다 앞에 둡니다. 특히 HTTP와 Googlebot 문서 크기 같은 관측된 수집 문제를 우선합니다.

새 보고서에서는 반복 표현마다 같은 전체 작성 절차·편집 가이드를 재인쇄하지 않습니다. 표현별 횟수·원문·위치·방향·작성 틀·완료 확인은 남기고 공통 실행 순서는 한 번 안내합니다. 편집 가이드도 실제 원문·선택자·설정·제안·완료 기준·출처 중심으로 정리합니다. 공식 SEO 점검에는 적용된 관측·해석·실행 순서·출처를 보존하고, 적용되지 않은 전체 문서 사전과 속성 목록의 중복 수록을 생략합니다. 긴 시각화 카드의 발췌는 제한하되 상세 원문은 유지합니다.

## 검증

- `npm test`: 334개 통과. 신규 근거 검증 5개에는 연락처/H1/CTA의 잘못된 확정 판정, ALT/미측정 분모, 저장 스키마와 안전하지 않은 URL, 키워드 일치, 브랜드 질문 편향, PDF 경계와 긴 H1, 타 사이트 근거 배제·수집 문제 우선순위 검사를 포함합니다.
- `npm run typecheck`: 통과.
- `npm run build`: 포켓 앱을 포함한 운영 빌드 통과. 로컬에서 운영 마이그레이션은 실행하지 않습니다.
- `node --import tsx --test tests/*.integration.ts`: 격리 Redis로 저장·승인·권한·활동·만료 관련 38개 통과. 실제 고객 저장소·메일을 사용하지 않습니다.
- `tests/browser/evidence-review.cjs`: 가상 응답을 사용한 로컬 운영 빌드 검사입니다. 320/390/768/1440px 가로 넘침 없음, 브라우저 실행 오류 없음, 근거 펼치기·질문 유형별 지표·요약/상세 PDF 생성과 실제 다운로드 확인.
- 실제 PDF를 Pretendard로 렌더링하여 요약·근거 카드·질문별 관측 화면을 시각 점검했습니다. 문서의 수학적 경계 검사와 실제 파일 검수를 구분합니다.

브라우저 검사에는 Playwright와 Chromium이 필요합니다. 기본 Playwright 설치를 사용하거나, 격리된 공식 npm 런처의 절대 모듈 경로를 `EVIDENCE_CHROMIUM_MODULE`로 지정할 수 있습니다. 앱 의존성을 추가하지 않습니다. 이 검사는 합성 데이터의 UI·내보내기 검증이며, 실제 OpenAI·네이버 응답이나 운영 계정에서 새 분석을 실행했다는 의미가 아닙니다.

진단 방식은 `marketing-diagnosis-2026-10-v11-evidence`로 분리합니다. 다른 방식의 점수 차이를 개선 성과로 비교하지 않으며 관측 항목의 상태·원문을 대조합니다.
